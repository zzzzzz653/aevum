ФУНДАМЕНТАЛЬНЫЕ ПРИНЦИПЫ (ВСЕ ЭТАПЫ)
###############################################################################

1. DATA-ORIENTED DESIGN
   ВСЁ лежит в SoA (Structure of Arrays). Никаких объектов с виртуальными
   методами и указателями на куче для горячих данных.

2. GPU-FIRST, CPU-COMPATIBLE
   Единый лэйаут данных для CPU и GPU. Структуры сразу проектируются под
   выравнивание GPU (std430). CPU-режим — те же данные, тот же код,
   просто executing на CPU через заглушки.

3. TRIPLE BUFFERING GPU↔CPU
   Три буфера: GPU Compute пишет в BUFFER_A, GPU Render читает BUFFER_B,
   CPU Reader асинхронно читает BUFFER_C. Ротация по готовности fence.
   CPU НИКОГДА не ждёт GPU. Максимальная задержка — 2 кадра.

4. DETERMINISTIC-READY
   Два режима с первого дня:
   - FAST: производительность, разрешён параллелизм, float-оптимизации
   - DETERMINISTIC: строгий порядок операций, программные sin/cos/sqrt,
     фиксированный порядок обхода, идентичность на разных архитектурах

5. PROFILER-INTEGRATED
   Замеры CPU (std::time::Instant) и GPU (timestamp queries) для каждой
   системы. Per-frame статистика в debug, агрегированная в release.

6. RECORD/REPLAY — ТРЁХУРОВНЕВАЯ СИСТЕМА
   - Hot Ring Buffer: последние K=1000 тиков в памяти (всегда, ~бесплатно)
   - Event-Triggered Snapshots: автосохранение по детекторам событий
   - Deterministic Replay: seed + начальное состояние → любой тик
     пересчитывается побитово

7. SYSTEMIC EVENTS, НЕ SCRIPTED
   Все события возникают из комбинации факторов среды.
   Никаких "spawn_enemy_at_tick_500".

8. SENSOR REALISM
   Никакой прямой информации об объектах. Только сырые данные + шум.
   Агент должен САМ научиться интерпретировать сенсоры.

9. TENSOR-FIRST
   Все данные для нейросетей — тензоры на GPU.
   Никаких копирований CPU↔GPU для сенсоров и моторных команд.

10. STREAMING WORLD
    Только активные чанки в памяти. Остальное спит или на диске.

--- ENTITY ---

EntityId:
    index: u32           # индекс в архетипе
    generation: u32      # поколение (alive/dead проверка)

packed: u64 = ((generation as u64) << 32) | (index as u64)

--- COMPONENT MASK ---

ComponentMask:
    bits: u64            # битовая маска компонентов (до 64 типов)

--- BODY TYPE ---

BodyType:
    Static      = 0      # не интегрируется, не двигается (земля, стены)
    Dynamic     = 1      # интегрируется, реагирует на силы
    Kinematic   = 2      # не интегрируется, двигается скриптом

--- COLLISION SHAPE ---

CollisionShape:
    tag: u32             # Sphere=0, Box=1, Capsule=2, Cylinder=3,
                          # ConvexHull=4, HeightField=5, None=6
    # Sphere:
    radius: f32
    # Box:
    half_extents: [f32; 3]
    # Capsule:
    capsule_radius: f32
    capsule_half_height: f32
    # Cylinder:
    cylinder_radius: f32
    cylinder_half_height: f32
    # ConvexHull:
    hull_vertex_offset: u32
    hull_vertex_count: u32
    # HeightField:
    hf_width: u32
    hf_height: u32
    hf_data_offset: u32

Примечание: union с фиксированным размером 32 байта.

--- RIGID BODY ---

RigidBody:
    body_type:      BodyType
    shape:          CollisionShape
    mass:           f32
    inv_mass:       f32
    inertia:        [f32; 9]       # mat3
    inv_inertia:    [f32; 9]
    material_id:    u32
    sleeping:       bool

--- INTEGRATOR CONFIG ---

IntegratorConfig:
    dt_physics:         f32         # 0.01 (100 Гц) — базовый шаг физики
    substeps:           u32         # 4-8 подшагов на тик
    solver_iterations:  u32         # 5-10 XPBD итераций на substep
    gravity:            [f32; 3]   # (0, -9.81, 0)
    linear_damping:     f32         # 0.999
    angular_damping:    f32         # 0.995
    sleep_threshold:    f32         # 0.01
    sleep_frames:       u32         # 60

--- CONSTRAINT BATCH (GPU-ready, SoA) ---

ConstraintBatch:
    constraint_type:    Vec<u32>       # Distance=0, Hinge=1, Ball=2,
                                       # Contact=3, Muscle=4
    body_a:             Vec<u32>
    body_b:             Vec<u32>
    rest_value:         Vec<f32>       # rest length / rest angle
    lambda:             Vec<f32>       # множители Лагранжа (warm start)
    compliance:         Vec<f32>      # податливость (XPBD)
    local_pos_a:        Vec<[f32; 3]>
    local_pos_b:        Vec<[f32; 3]>
    # Для Hinge:
    local_axis_a:       Vec<[f32; 3]>
    local_axis_b:       Vec<[f32; 3]>
    angle_min:          Vec<f32>
    angle_max:          Vec<f32>
    # Для Muscle:
    current_activation: Vec<f32>       # [0, 1] от нейросети
    max_force:          Vec<f32>
    rest_length_min:    Vec<f32>
    rest_length_max:    Vec<f32>

--- CONTACT POINT ---

ContactPoint:
    position:           [f32; 3]
    normal:             [f32; 3]
    penetration:        f32
    impulse_normal:     f32
    impulse_tangent:    [f32; 2]
    contact_id:         u64

--- CONTACT MANIFOLD ---

ContactManifold:
    entity_a:           u64
    entity_b:           u64
    contacts:           SmallVec<[ContactPoint; 4]>
    age:                u32
    material_pair:      (u32, u32)

    color:              [f32; 4]

    damage_threshold:   f32         # минимальный impulse для повреждения

--- DISEASE (СИСТЕМНАЯ, БЕЗ ПРЯМОЙ ЛЕТАЛЬНОСТИ) ---

Disease:
    disease_id:         u64
    name:               String
    
    # Распространение
    transmission:       TransmissionType
    infection_radius:   f32         # для airborne/contact
    infection_prob:     f32         # вероятность заражения при контакте
    incubation_ticks:   u32         # скрытый период
    
    # Симптомы (ВСЕ опциональны, комбинируются)
    symptoms:           Vec<Symptom>
    
    # Длительность
    duration_min:       u32         # минимальная длительность (тиков)
    duration_max:       u32         # максимальная
    
    # Мутации
    mutation_prob:      f32         # вероятность мутации при передаче
    mutation_mask:      u64         # какие симптомы могут мутировать

TransmissionType:
    Contact,            # прямой контакт существ
    Airborne,           # воздух (через smell diffusion field!)
    Waterborne,         # вода
    Vector              # переносчик (другое существо)

Symptom:
    symptom_type:       SymptomType
    intensity:          f32         # 0..1, сила симптома
    progression_ticks:  u32         # за сколько тиков нарастает до полной силы

SymptomType:
    # СЕНСОРНЫЕ СИМПТОМЫ (добавляют шум)
    VisionNoise,            # увеличивает σ шума в зрении
    HearingNoise,           # увеличивает σ шума в слухе
    SmellNoise,             # увеличивает σ шума в обонянии
    TouchNoise,             # увеличивает σ шума в осязании
    ProprioceptionNoise,    # увеличивает σ шума в проприоцепции
    
    VisionDistortion,       # хроматическая аберрация / blur
    HearingLoss,            # снижение общей громкости
    SmellLoss,              # снижение концентраций
    
    # МОТОРНЫЕ СИМПТОМЫ
    MuscleWeakness,         # снижение max_force всех мышц
    MuscleTremor,           # случайный шум в muscle_activation
    MuscleDelay,            # задержка применения activation
    CoordinationLoss,       # случайная инверсия сигналов (L/R путаница)
    JointStiffness,         # увеличение stiffness суставов
    
    # МЕТАБОЛИЧЕСКИЕ СИМПТОМЫ
    EnergyDrain,            # повышенный basal_metabolism
    Fatigue,                # снижение max_velocity
    TemperatureShift,       # отклонение body_temperature от нормы
    
    # КОГНИТИВНЫЕ (влияют на НЕЙРОСЕТЬ — для Aevum)
    AttentionDeficit,       # случайный сброс saliency
    MemoryImpairment,       # увеличение шума в replay buffer
    Confusion,              # случайная замена L_t на шум

###############################################################################
GPU ↔ CPU DATA FLOW (TRIPLE BUFFERING)
###############################################################################

Три буфера: BUFFER_A, BUFFER_B, BUFFER_C

Frame N:
    GPU Compute: пишет результат в BUFFER_A
    GPU Render:  читает BUFFER_B (результат кадра N-1)
    CPU Reader:  асинхронно читает BUFFER_C (результат кадра N-2)

Frame N+1:
    GPU Compute: BUFFER_B
    GPU Render:  BUFFER_C
    CPU Reader:  BUFFER_A

Правила:
    1. GPU никогда не ждёт CPU (fence-based синхронизация)
    2. CPU reader — отдельный поток, только опрашивает fence
    3. Если данные не готовы — CPU использует предыдущий кадр
    4. Для физики с субстеппингом задержка в 2 кадра незаметна

Данные GPU → CPU:
    - Статистика коллизий (количество, типы)
    - Данные сенсоров существ (VisionData, HearingData, SmellData)
    - Профилировочные тайминги (GPU query pool)
    - События (Event)

Что остаётся на GPU:
    - Позиции, скорости, трансформации
    - Рендер читает напрямую из GPU-буферов физики (без roundtrip)
    - SmellField (diffusion grid)
    - ClimateState (температура, влажность, ветер)

###############################################################################
ЭТАП 2: ФИЗИКА + ТЕЛА СУЩЕСТВ
###############################################################################

2.1 BROADPHASE — SPATIAL HASH GRID (GPU)
    - Ячейки фиксированного размера (1 метр)
    - Radix sort пар (entity_id, cell_hash)
    - Prefix sum для cell_offsets
    - Проверка только внутри ячейки и 26 соседних
    - Цель: 10 мкс на 100k объектов

2.2 NARROWPHASE — GJK/EPA
    - GJK: проверка пересечения выпуклых форм (Sphere, Box, Capsule, Cylinder, ConvexHull)
    - EPA: penetration_depth, contact_normal, contact_point
    - Warm start: кэширование симплекса GJK
    - До 4 контактных точек на пару

2.3 CONTACT MANAGER — PERSISTENT MANIFOLDS
    - ContactPoint: position, normal, penetration, accumulated_impulse
    - Feature-based matching между тиками (contact_id)
    - Трение: кулоновская модель (clamp tangent_impulse по friction_limit)
    - Warm start: накопленные импульсы

2.4 XPBD SOLVER
    - ConstraintBatch: SoA, GPU-ready
    - Типы ограничений: Distance, Hinge, Ball, Contact, Muscle
    - Compliance вместо жёсткости → стабильность
    - 5-10 итераций на substep
    - 4-8 substeps на физический тик

2.5 MATERIAL SYSTEM
    - Material: friction, density, restitution, compliance, damage_threshold,
      damage_multiplier, deformation, sound_absorption, burn_rate, thermal_conductivity
    - Загрузка из YAML
    - Pair cache для контактных свойств
    - Влияние на: коллизии, повреждения, звук, огонь, температуру

2.6 CREATURE BUILDER
    - build_from_json(path) → CreatureInstance
    - Части тела: Sphere, Capsule, Box
    - Суставы: Hinge (колено, локоть), Ball (плечо, бедро)
    - Мышцы: XPBD distance constraint с переменной rest_length
    - Рекурсивное построение иерархии

2.7 MUSCLE SYSTEM
    - rest_length = lerp(max, min, activation)
    - activation: [0, 1] от нейросети
    - max_force: предельная сила
    - ТОЛЬКО тянет (однонаправленная)
    - Пассивное сопротивление при растяжении

2.8 STABILITY GUARANTEES
    - NO FOOT SLIPPING: высокое трение стоп + warm start
    - NO JOINT JITTER: XPBD compliance + substeps
    - NO CONSTRAINT EXPLOSION: ограниченные итерации + warm start
    - NO ENERGY INJECTION: damping + energy audit
    - NO TUNNELING: CCD + спекулятивные контакты
    - Тесты: существо стоит 10 000 тиков без дрифта

###############################################################################
ЭТАП 3: РЕАЛИСТИЧНЫЙ МИР
###############################################################################

3.1 TERRAIN
    - Heightfield: Perlin/Simplex noise, multiple octaves
    - Биомы по высоте и влажности: ocean, beach, grassland, hills, mountains, snow
    - Билинейная интерполяция высоты
    - Нормали из градиента
    - LOD: дальние чанки грубее
    - Streaming: загрузка/выгрузка чанков

3.2 WATER (SHALLOW WATER)
    - Height-field представление
    - Уравнения мелкой воды: dh/dt, du/dt, dv/dt
    - Semi-Lagrangian advection
    - Плавучесть: F = density * submerged_volume * g
    - Сопротивление: F_drag
    - Визуализация: полупрозрачная плоскость + нормали

3.3 CLIMATE
    - Поля: temperature, humidity, pressure, wind, cloud, precipitation
    - Диффузия + солнечный нагрев + adiabatic cooling
    - Wind: градиент давления + Кориолис
    - Обновление раз в 10-100 тиков (GPU compute)

3.4 WEATHER
    - Облака: конденсация при saturation
    - Дождь: precipitation > порога
    - Снег: precipitation + temperature < 273 K
    - Влияние на: видимость, звук, запахи, огонь

3.5 SEASONS
    - Цикл: Spring → Summer → Autumn → Winter
    - Длительность: 2 160 000 тиков на сезон (~6 часов реального времени)
    - Влияние: temperature_offset, day_length, precipitation_mul

3.6 WORLD STREAMING
    - Активные чанки: N×N вокруг камеры/существ
    - Чанк: 64×64 метров, terrain + water + objects + creatures
    - Подгрузка по мере движения фокуса
    - Выгрузка: сериализация → освобождение памяти

###############################################################################
ЭТАП 4: СЕНСОРЫ
###############################################################################

4.1 VISION (RGB КАМЕРА)
    - GPU render-to-texture для каждого глаза
    - Resolution: 32×32 (можно 64×64)
    - FOV: 1.2 радиан (~70°)
    - max_distance: 50 м
    - Шум:
      - Гауссов шум: σ = 0.02 + 0.05 * (1 - light_level)
      - Motion blur при быстром движении
      - Атмосферное затухание (туман, дождь, снег)
      - + дополнительные шумы от болезней
    - Выход: RGB тензор [32, 32, 3] float32 [0, 1]
    - Оптимизация: групповой рендер всех глаз за один проход

4.2 HEARING
    - Источники: SoundEvent (шаги, столкновения, крики, гром)
    - Затухание: intensity / (1 + distance² * attenuation)
    - Окклюзия: raycast на препятствия → ×0.1
    - Частотная фильтрация: высокие затухают быстрее
    - Частотные полосы: 8 (настраивается)
    - Шум: σ = 0.05, направленный шум ±5°
    - Выход: [intensity, direction(3), spectrum(N)]

4.3 SMELL
    - Diffusion field на GPU (текстура)
    - Chemical_signature: 16-мерный вектор
    - Уравнение диффузии: dC/dt = D∇²C - decay*C + sources
    - Адвекция ветром
    - Шум: σ = 0.1 + 0.2 * wind_speed
    - Выход: [f32; D] концентрации

4.4 TOUCH
    - Чтение ContactManifold для тела
    - Данные: force, normal, friction, material_id, temperature
    - Шум: σ = 0.01 * max_force
    - Выход: [force, normal(3), friction(2), material_id, temperature]

4.5 PROPRIOCEPTION
    - Все углы суставов, угловые скорости, моменты
    - Активация мышц, натяжение
    - IMU: акселерометр, гироскоп (с дрейфом)
    - Внутреннее: energy_level, damage_level, body_temperature
    - Шум: σ = 0.01 на все значения

4.6 ELECTRO / MAGNETO (опционально)
    - Electro: электрические поля (мышцы, молнии), ~1/r²
    - Magneto: магнитное поле Земли + аномалии

ЭТАП 5: СЛУЧАЙНЫЕ СОБЫТИЯ
###############################################################################

ОБЩИЙ ПРИНЦИП: ВСЕ СОБЫТИЯ SYSTEMIC.
Возникают из комбинации факторов среды. Никаких скриптов.

5.1 EVENT SYSTEM
    - Проверка условий каждый тик
    - Интенсивность, радиус, длительность, эпицентр
    - Влияние на мир через модификацию компонентов

5.2 WILDFIRE
    Условия:
      - temperature > 300 K
      - humidity < 0.3
      - lightning_strike ИЛИ lava ИЛИ existing_fire
      - fuel: burn_rate > 0
    Распространение:
      - По wind
      - По fuel (burn_rate материала)
      - В гору быстрее
    Влияние:
      - Уничтожение растительности
      - Damage существам
      - Smoke: smell source + vision obstruction
      - Material: → ash (burn_rate=0)
      - Регенерация через N тиков: ash → grass
    Тушение:
      - Дождь (precipitation > 0.5)
      - Отсутствие fuel
      - Вода

5.3 EARTHQUAKE
    Условия:
      - Тектонические линии на карте
      - Нарастающая вероятность
    Эффект:
      - Вибрация: синусоидальное смещение Static
      - Амплитуда/частота от intensity
      - Duration: 100-500 тиков
    Влияние:
      - Изменение terrain (оползни)
      - Damage всем объектам
      - Падение существ
      - Афтершоки
      - Триггер цунами (в океане)

5.4 FLOOD
    Условия:
      - Длительные осадки
      - Цунами (earthquake в океане)
    Эффект:
      - Подъём water_height
      - Течение
    Влияние:
      - Затопление низменностей
      - Гибель растительности
      - Миграция или гибель существ
      - Material: → mud

5.5 STORM (УРАГАН)
    Условия:
      - Большой градиент температуры
      - Высокая влажность
      - Над океаном
    Эффект:
      - Экстремальный ветер (5-10×)
      - Сильные осадки
      - Движется по карте
    Влияние:
      - Силы на все объекты
      - Разрушение структур
      - Распространение запахов

5.6 DROUGHT
    Условия:
      - Длительное отсутствие осадков
      - Высокая температура
    Эффект:
      - humidity → 0.1
      - water_height снижается
      - water_deficit для растений
    Влияние:
      - Гибель растительности
      - Повышенная вероятность пожаров
      - Миграция существ

5.7 VOLCANO (опционально)
    - Стационарный источник
    - Извержение: лава, пепел, пирокластические потоки
    - Влияние: terrain changes, global cooling (пепел)

5.8 DISEASE OUTBREAK
    Условия:
      - Высокая плотность существ
      - Низкая температура (ослабленный иммунитет)
      - Наличие disease в популяции
    Эффект:
      - Spawn Disease в регионе
      - Распространение через transmission_type

--- DISEASE SYSTEM RUNTIME ---

DiseaseSystem::update(world, dt):
Для каждого заражённого существа:
1. Если инкубационный период прошёл:
symptom_progress += dt / progression_ticks  # нарастание 0→1
current_intensity = symptom_progress * symptom.intensity
2. Применить симптомы к сенсорам и мышцам:
- VisionNoise: увеличить σ в VisionSensor
- MuscleWeakness: умножить max_force всех мышц на (1 - intensity)
- MuscleTremor: добавить random noise к activation
- CoordinationLoss: случайная инверсия L/R активации
- EnergyDrain: увеличить basal_metabolism
- ... и т.д.
3. Проверить duration: если remaining_ticks == 0 → выздоровление
4. Сохранить в ImmuneMemory:
- Какие симптомы были, их сила
- НЕ даёт бонусов, только запись опыта

DiseaseSystem::transmit(world):
Для каждого заражённого:
Если transmission == airborne:
- Найти всех существ в infection_radius
- Вероятность заражения = infection_prob * плотность
Если transmission == contact:
- Проверить ContactManifold с другими существами
- При контакте: вероятность = infection_prob
Если transmission == waterborne:
- Проверить, находятся ли в одном водоёме
При заражении:
- Если есть mutation_prob: возможна мутация симптомов
- Создать новый Infection с disease_id (возможно, новым)

DiseaseSystem::mutate(parent_disease, world_rng):
# При передаче:
1. С вероятностью mutation_prob:
a. Выбрать symptom из mutation_mask
b. Изменить intensity на ±20% (clamp 0.1-1.0)
c. ИЛИ добавить новый symptom из mutation_mask
d. ИЛИ (если существо заражено двумя болезнями) —
рекомбинировать симптомы от обеих
2. Создать новый disease_id с новой комбинацией
3. Записать в реестр болезней

--- IMMUNE MEMORY (АДАПТАЦИЯ, НЕ ИММУНИТЕТ) ---

ImmuneMemory НЕ изменяет параметры болезни напрямую.
Это данные, которые ПОДАЮТСЯ В НЕЙРОСЕТЬ Aevum.

При повторном заражении:
- Aevum получает immune_memory как дополнительный вход:
[disease_id, exposure_count, symptom_1_type, symptom_1_intensity, ...]
- Мозг может:
- Узнать знакомую болезнь по первым симптомам
- Заранее усилить другие сенсоры (меньше полагаться на зрение)
- Изменить стратегию движения (медленнее, осторожнее)
- Искать убежище

Это НЕ хардкод. Это обучение.
При первой встрече с болезнью агент страдает.
При повторной — знает, как компенсировать.

РЕШЕНИЯ ДЛЯ УЗКИХ МЕСТ
###############################################################################

Проблема: GPU → CPU transfer latency
Решение: Triple buffering + CPU reader thread + tolerance to 2-frame latency

Проблема: Angular constraints сложность
Решение: Exp map tangent space + hinge-only first + постепенное усложнение

Проблема: Friction instability
Решение: Persistent contact manifolds + warm starting + cached tangent impulses

Проблема: Snapshot layout changes
Решение: Stable binary schema layer поверх ECS

Проблема: Floating-point determinism
Решение: Два режима: Fast и Deterministic

Проблема: EventBus contention
Решение: Per-thread local event buffers + merge

Проблема: Chunk lookup overhead
Решение: Sparse HashMap с Morton/Z-order ключами

Проблема: Hot Ring память
Решение: Дельта-компрессия + опциональная lossy compression

Проблема: Deterministic replay производительность
Решение: Комбинировать с Event-Triggered снапшотами как чекпоинтами

Проблема: Vision sensor performance (много существ)
Решение: Групповой рендер всех глаз за один проход GPU

Проблема: Smell field память
Решение: Только для активных чанков, разрешение 1/4 от terrain, GPU

Проблема: Fire spread performance
Решение: Клеточный автомат на GPU, обновление только горящих/соседних клеток

Проблема: Disease tracking overhead
Решение: Только для заражённых существ, ленивое обновление ImmuneMemory

ФИНАЛЬНЫЕ ЗАМЕЧАНИЯ
###############################################################################

1. ЭТО НЕ ИГРОВОЙ ДВИЖОК.
   Это вычислительный биом для эволюции. Визуализация — лишь окно.
2. STABILITY FIRST.
   Лучше 10 стабильных существ, чем 1000 дёргающихся.
   XPBD + substeps + warm start — ключ к стабильности.
3. NO CHEATING.
   Сенсоры не получают прямую информацию. Болезни не убивают напрямую.
   Мозг сам учится интерпретировать и компенсировать.
4. SYSTEMIC, NOT SCRIPTED.
   События возникают из среды, не из скриптов.
   Пожар = температура + сухость + молния.
5. TENSOR-FIRST.
   Все данные сенсоров — тензоры на GPU.
   Никаких копирований CPU↔GPU для neural pipeline.
6. PROFILER FROM DAY ONE.
   Без него оптимизация — гадание.
7. RECORD/REPLAY — ИНФРАСТРУКТУРА.
   Трёхуровневая система: Hot Ring (мгновенно), Event-Triggered (события),
   Deterministic (побитово).
8. DISEASES AS SENSOR/MUSCLE MODIFIERS.
   Никаких "if lethal > random: die".
   Только: зрение зашумлено, мышцы слабее, координация нарушена.
   Смерть = последствия симптомов (голод, падение, хищник).
9. IMMUNITY = BRAIN ADAPTATION.
   Иммунная память — вход для нейросети Aevum.
   Мозг учится компенсировать знакомые симптомы.
10. 300 FPS НА 100K СФЕР — РЕАЛИСТИЧНАЯ ЦЕЛЬ.
    Если фундамент не тянет это — всё остальное не взлетит.
